# Календарь оплат и журнал действий

## Что реализовано на фронтенде

Календарь использует действующий `GET /api/v1/payment-occurrences`, детализация и отметка оплаты — прежние `GET/PATCH /payment-occurrences/{id}`. Обе роли могут работать с календарём. Журнал действий пока доступен администратору; серверный контракт журнала и правила доступа требуется согласовать с backend.

Новые зависимости и изменения backend, базы данных, миграций, Docker и Telegram не требуются для интерфейса.

## Календарь

В разделе «Календарь» показаны обязательства по **сроку оплаты**, а не по фактическому дню оплаты. Месячная сетка начинается с понедельника. День раскрывает полный список своих платежей; на телефоне используется список по дням. Нажатие на платёж открывает общую панель: отметить оплату, исправить дату, отменить отметку, перейти в историю регулярного платежа. Прекращённые платежи сохраняются.

Месяц, выбранный день, валюта и статус сохраняются в `#calendar?...`; обновление страницы и переходы назад/вперёд восстанавливают состояние. «Сегодня» использует общую бизнес-дату: в демо 23 октября 2026 года, в настоящем режиме текущий день по МСК.

Для месяца загружаются все страницы периодов, по 100 записей. Незавершённая или противоречивая выдача отображается как ошибка с повтором, а не как полный месяц. Скрытого лимита отображаемых платежей нет. Суммы — строки, валюты не складываются между собой. Календарные даты рассчитываются без преобразования в часовой пояс браузера. Окончательные даты и статусы приходят с сервера.

Календарь показывает уже сформированные сервером периоды. Пустой будущий месяц не гарантирует отсутствия расходов: backend может ещё не сформировать эти периоды. Фронтенд не создаёт обязательства по прогнозу.

## Журнал

Журнал — список событий с автором, временем по МСК, действием и объектом изменения. Есть поиск по объекту/автору, фильтры по действию, автору и датам, страницы и панель подробностей со значениями до/после. Фильтры и страница сохраняются в `#activity?...`. «Сбросить» очищает также неприменённые поля и ошибку диапазона.

В текущем `main` нет серверного API аудита. В `real` показывается «Серверный журнал ещё не подключён»; запрос к несуществующему маршруту не отправляется, примеры и нулевой счётчик не подставляются. После согласования backend-контракта точкой подключения служит `src/api/activity.ts`.

В `mock` события — демонстрационные, хранятся только в памяти вкладки и сбрасываются при перезагрузке. Успешные изменения платежей и пользователей добавляют новые события. Ошибки и действия без изменения данных не создают ложных записей. Демо-журнал не является долговечным серверным аудитом.

### Модель отображения для согласования с backend

`src/types/activity.ts` описывает **предлагаемую модель фронтенда**, а не уже существующий HTTP-контракт. Событию нужны `id`, `occurred_at` (timestamp UTC), `actor: {id, username}`, `action`, `entity: {type, id, title}` и `changes: [{field, label, before, after}]`. Для платёжных событий `entity.id` — ID регулярного платежа, чтобы открыть всю его историю. Снимки автора и названия объекта должны сохраняться после удаления/переименования.

Действия: создание/прекращение платежа, отметка/отмена оплаты, изменение фактической даты, создание/изменение/удаление пользователя, смена собственного пароля. Время события задаёт сервер. Только успешные зафиксированные операции должны попадать в долговечный аудит.

В журнал не передаются и не показываются пароли, их хеши, cookie, CSRF и другие секреты. Для смены пароля отображается только факт изменения. Клиентский интерфейс и скрытая вкладка не заменяют серверную проверку прав.

## Проверка

- Календарь: смена месяца, «Сегодня», фильтры, выбранный день, длинные названия и крупные суммы, полный список дня, оплата и переход в историю.
- Журнал: фильтры/поиск/пагинация, сброс неприменённых значений и ошибочного диапазона, подробности, события после изменений, отсутствие у обычной роли.
- Обновление и Back/Forward, мобильная и настольная раскладка, клавиатура, уменьшенная анимация, загрузка/ошибка/пустой результат.
- Автоматические проверки: `npm test`, `npm run build`, `npm run lint`.

### Результат проверки этой версии

`npm test`: 46/46; `npm run build` (TypeScript и Vite), `npm run lint`: успешно. В браузере пройдены оплата из календаря и появление события, переход из подробностей в историю, фильтры/ошибочный диапазон/сброс, поиск, пагинация и обновление ссылки. Проверены обе роли, Tab/Shift+Tab/Escape в подробностях, пустой журнал, ошибка журнала, ошибка календаря и пустой будущий месяц. На ширинах 320, 390 и около 761 px проверены длинные названия и сумма `999999999999.99`; горизонтального переполнения страницы и обрезания суммы нет. Real-адаптер проверен unit-тестом: не вызывает fetch и возвращает AUDIT_NOT_AVAILABLE. Настоящий backend аудита не тестировался, поскольку такого API пока нет.
