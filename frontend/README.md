# Invoice Keeper

Рабочая панель регулярных платежей на React, Vite и TypeScript. Светлая и тёмная темы, раздельная сводка RUB/USD/EUR и логотип é: при наведении или клавиатурном фокусе он раскрывает название Invoice Keeper.

Главный экран показывает [просрочки за всё время и компактную мобильную сводку](../docs/frontend/overdue-workspace.md). На телефоне валюты раскрываются по отдельности, фильтры открываются по кнопке, все разделы доступны через выбор в шапке.

## Запуск

Общий запуск через Docker описан в [корневом README](../docs/operations/deployment.md#фронтенд-в-docker). Docker по умолчанию использует настоящий API; для отдельной демонстрации явно задайте `FRONTEND_API_MODE=mock` и пересоберите frontend. Node.js на компьютере для Docker не нужен. Команды ниже выполняются в папке `frontend` и предназначены для разработки с Vite, где демо остаётся режимом по умолчанию.

Проверенное окружение: **Node.js 24.22.1, npm 11.6.2**. Версии указаны в `package.json`, `.node-version` и `.npmrc`; зависимости закреплены в `package-lock.json`.

```bash
npm ci
npm run dev
```

Откройте `http://localhost:5173`. По умолчанию работает демонстрационный транспорт, сервер API для просмотра не нужен.

```bash
npm test
npm run typecheck
npm run lint
npm run build
npm run preview
```

Последняя команда показывает собранную версию на `http://localhost:4173`.

## Демо

На экране входа кнопки ролей заполняют поля, затем нажмите «Войти».

| Роль | Логин | Пароль для демонстрации |
| --- | --- | --- |
| Администратор | admin | Admin123! |
| Пользователь | ivan | example-password-only |

Демо фиксировано на **23.10.2026 по МСК**. Общая дата, подпись и временные отметки задаются в `src/config/demo.ts`; форма нового платежа использует тот же день, даже если на компьютере другая дата. Оно использует примеры из контракта и дополнительные записи для проверки разных состояний. Изменения хранятся в памяти текущей вкладки и сбрасываются при перезагрузке; в localStorage сохраняется только имя демонстрационной сессии. Это поведение не используется для реальной авторизации.

## Подключение API

Скопируйте `.env.example` в `.env.local` и задайте:

```dotenv
VITE_API_MODE=real
VITE_API_BASE_URL=/api/v1
API_PROXY_TARGET=http://127.0.0.1:8000
```

Перезапустите Vite. В режиме `real` клиент отправляет реальные HTTP-запросы; автоматической подмены демо-данными при ошибке нет. `/api` в dev-режиме проксируется к API. Сервер должен разрешать фактический origin интерфейса, например `http://localhost:5173`. Заголовок Origin выставляет браузер; прокси сохраняет его.

Для развёртывания раздайте `dist/` и `/api/v1` с одного origin через сервер или reverse proxy. Dev-прокси Vite не является production-прокси. Параметры `VITE_*` встраиваются во время сборки, поэтому после изменения режима нужна новая сборка.

Сессия: cookie с `credentials: include`; клиент получает CSRF из `/auth/login` и `/auth/me`, хранит токен в памяти и передаёт `X-CSRF-Token` в изменяющих запросах, кроме входа. `401` завершает локальное состояние авторизации и возвращает экран входа. При сетевой ошибке выхода сессия не считается подтверждённо закрытой.

После подтверждённого выхода остальные открытые вкладки этого origin получают сигнал через `BroadcastChannel` и автоматически перезагружаются: старые запросы отменяются, закрытые данные и формы удаляются, сессия заново проверяется сервером. Сигнал не содержит токенов или данных пользователя. Независимые демонстрационные вкладки этот механизм не используют.

## Возможности

- Периоды с фильтрами по срокам, валюте и статусу, пагинацией и отдельной историей выбранного правила. Прекращённые правила и их периоды остаются доступны.
- Подтверждение оплаты конкретного периода, отмена отметки и исправление фактической даты вынесены в отдельную форму. Название открывает карточку платежа; редактирование и удаление неоплаченного периода доступны прямо в строке. Срок обязательства не изменяется. Статусы: «Не оплачено», «Просрочено», «Оплачено», «Оплачено с опозданием».
- Итоги приходят отдельным запросом `/payments/summary` по всем обязательствам выбранного интервала, независимо от страницы, валютного фильтра или вкладки статуса списка. RUB, USD и EUR показаны отдельно; «из них просрочено» входит в неоплаченное.
- Администратор создаёт разовые и регулярные платежи через общую форму на главной и в разделе «Регулярные»: раз в N дней, недель, месяцев или лет. После создания с главной открываются периоды нового платежа, чтобы он был виден независимо от прежних фильтров. Можно изменить название, сумму и валюту, а разовый платёж сделать ежемесячным. Форма объясняет область изменения и показывает первые сроки; преобразование сохраняет оплату и чек, добавляя также пропущенные месяцы от исходного срока. Изменения регулярной суммы применяются со следующего месяца; название общее для всей истории. Подробности — в [контракте платежей](../docs/api/payment-lifecycle.md).
- Администратор создаёт, редактирует и удаляет обычных пользователей. Администратор сервера не редактируется через список пользователей.
- Суммы передаются строками с двумя знаками после точки; интерфейс не суммирует деньги через Number. Календарные даты выводятся из компонентов строки без сдвига часового пояса. Статусы и опоздание берутся из API.
- Загрузка, пустые результаты, ошибки полей, отсутствие прав, обрыв сети и `503 PERIODS_NOT_READY` имеют отдельные состояния. При 503 итоговые карточки не подменяются нулями.
- После изменений данные и итоги перечитываются. На время отправки повторные действия блокируются. Создающие POST отправляются один раз; после тайм-аута форма блокирует повтор и предлагает закрыть её и проверить список.
- На телефоне таблицы становятся карточками. Поддерживаются клавиатура, видимый фокус, ловушка фокуса в панелях, Escape, возврат фокуса и reduced motion.

## Проверочные сценарии демо

Добавьте параметр к адресу и перезагрузите вкладку. Сначала войдите в демо-учётную запись.

| Адрес | Проверка |
| --- | --- |
| `/?scenario=stress#payments` | Название до 200 символов и сумма 999999999999.99 |
| `/?scenario=periods-not-ready#payments` | 503 для сводки, список доступен |
| `/?scenario=forbidden#payments` | Запрет доступа к данным |
| `/?scenario=network-error#payments` | Ошибка сети после входа |
| `/?scenario=slow#recurring` | Задержка дольше тайм-аута клиента 12 секунд |

Для сброса сценария удалите параметр и перезагрузите страницу. В `real` эти параметры не подменяют ответы сервера.

## Структура

- `src/config/demo.ts` — фиксированная демо-дата и расчёт текущего дня по часовому поясу API в настоящем режиме.
- `src/components/SectionArt.tsx`, `PageHeader.tsx`, `PaymentStatus.tsx` — согласованная графика, заголовки и статусы.
- `src/types/api.ts` — DTO по контракту.
- `src/api/client.ts` — единый клиент, cookie, CSRF, ошибки, тайм-аут.
- `src/mocks/` — заменяемый демонстрационный сервер с контрактной валидацией и точными суммами через BigInt.
- `src/components/PaymentsView.tsx` — периоды, история, серверная сводка, оплата.
- `src/components/AdminViews.tsx` — административные формы.
- `src/components/UI.tsx` — доступные боковые панели и общие состояния.
- `src/lib/format.ts` — отображение денег и дат.
- [`visual-refresh.md`](../docs/frontend/visual-refresh.md) — обновление графики, логотипа и единой демо-даты.

- [`qa-report.md`](../docs/frontend/qa-report.md) — результаты проверок и границы проверки.
- [`docs/frontend/screenshots/`](../docs/frontend/screenshots/) — фактический интерфейс из браузера.
- [Контракт API](../docs/api/api-contract.md) и [командная работа](../docs/development/team-workflow.md) — общие документы проекта.

## Календарь оплат и журнал действий

Раздел «Календарь» показывает сроки на сетке месяца, в мобильном списке по дням и дневные итоги отдельно для RUB/USD/EUR. Детали и отметка оплаты используют действующее API. «Журнал» доступен администратору и показывает изменения, входы, неудачные попытки входа и выходы. В демо события остаются в памяти вкладки. Для настоящего API примените все миграции командой `alembic upgrade head` (текущий head — `0013`). Бюджет и подтверждения оплаты доступны в отдельных разделах и карточках периодов. В «Безопасности» обычный пользователь может отдельно подключить [оплату из Telegram](../docs/api/telegram-payments.md). Подробности: [дневные итоги](../docs/frontend/daily-totals.md), [журнал авторизации](../docs/operations/auth-journal.md).
