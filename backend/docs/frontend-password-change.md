# Смена собственного пароля: контракт для frontend

Реализация находится в `feat/auth`. Доступна обеим ролям: `admin` и `user`.
Пользователь меняет только свой пароль; `user_id`, логин и роль не передаются.
Новая миграция не нужна, используются существующие пользователи и сессии.

## Запрос

`POST /api/v1/auth/change-password`

Заголовки: `Content-Type: application/json`, актуальный `X-CSRF-Token`.
Запрос выполняется с `credentials: 'include'`; браузер передаёт cookie и Origin.
Не нужно пытаться устанавливать Origin вручную из JavaScript.

```json
{
  "current_password": "old-password-example",
  "new_password": "new-password-example"
}
```

Оба поля обязательны и принимают только строки. `current_password` — 1–128
символов, `new_password` — 8–128 символов и должен отличаться от текущего.
Пароли не обрезаются и не нормализуются: не применять `.trim()`.
Подтверждение нового пароля проверяет форма; `confirm_password` в API не отправлять.
Неизвестные поля и любые query-параметры отклоняются с 422.

## Успех и сессии

Успех — `200`, заголовки `Set-Cookie` и `Cache-Control: no-store`, тело как у login/me:

```json
{
  "user": {
    "id": "9b3a2a64-c7a9-4dd0-98f4-e5e1458ad1d6",
    "username": "ivan",
    "role": "user",
    "created_at": "2026-10-23T09:00:00Z"
  },
  "csrf_token": "new-csrf-token-example"
}
```

Текущий браузер остаётся авторизованным, но получает новый токен сессии и новый
CSRF-токен. Cookie обновляет сам браузер; JS её не читает. **Обязательно заменить
CSRF-токен в памяти значением из ответа до следующих изменяющих запросов.**
После перезагрузки страницы актуальный токен восстанавливается через `GET /auth/me`.
Во второй вкладке того же браузера cookie уже новая, но CSRF в памяти может быть
старым: при `403 CSRF_FAILED` перечитать `/auth/me`, не повторять мутацию автоматически.

Все остальные сессии этого пользователя отзываются; при следующем обращении они
получат `401 AUTH_REQUIRED`. Старую cookie нельзя использовать повторно. Сессии
других пользователей не меняются. Исходный срок действия текущей сессии сохраняется:
смена пароля не продлевает его ещё на семь дней. Старый пароль больше не подходит
для входа, новый подходит.

Смена хеша пароля, отзыв старых сессий и создание замены происходят одной
транзакцией. При ошибке сохранения прежний пароль и сессии сохраняются.

## Ошибки

Формат ошибок общий: `{ "error": { "code", "message", "details" } }`.
Каждый элемент `details` содержит `{ "field", "code", "message" }`.

| HTTP | error.code | Поведение формы |
|---|---|---|
| 422 | `CURRENT_PASSWORD_INVALID` | Ошибка у `current_password`; не разлогинивать пользователя. |
| 422 | `NEW_PASSWORD_UNCHANGED` | Ошибка у `new_password`: новый пароль совпадает с текущим. |
| 422 | `VALIDATION_ERROR` | Показать ошибки из `details`: REQUIRED, TOO_SHORT, TOO_LONG, INVALID_TYPE, UNKNOWN_FIELD и т.д. |
| 401 | `AUTH_REQUIRED` | Сессия отсутствует, истекла или отозвана; обычный переход к входу. |
| 403 | `CSRF_FAILED` | Получить актуальное состояние через `/auth/me`; запрос не применён. |
| 403 | `ORIGIN_NOT_ALLOWED` | Проверить адрес сайта и конфигурацию backend. |
| 429 | `PASSWORD_CHANGE_RATE_LIMITED` | Временно заблокировать отправку формы на время из `Retry-After` (секунды). |
| 400 | `INVALID_JSON` | Некорректный JSON запроса. |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | Запрос должен быть JSON. |

При прямом обращении к API с другого Origin сервер открывает заголовок
Retry-After через CORS, поэтому браузер может прочитать реальный срок блокировки.

Пример неверного текущего пароля:

```json
{
  "error": {
    "code": "CURRENT_PASSWORD_INVALID",
    "message": "Текущий пароль указан неверно",
    "details": [
      {
        "field": "current_password",
        "code": "CURRENT_PASSWORD_INVALID",
        "message": "Текущий пароль указан неверно"
      }
    ]
  }
}
```

По умолчанию разрешено 5 попыток за 15 минут на пользователя, суммарно по всем
его сессиям и IP. Считаются корректно сформированные запросы, включая неверный
текущий пароль и успешную смену. Лимит входа отдельный: его смена пароля не расходует.
Настройки backend: `PASSWORD_CHANGE_RATE_LIMIT_ATTEMPTS` и
`PASSWORD_CHANGE_RATE_LIMIT_WINDOW_SECONDS`. Отклонённые из-за пароля, валидации
или лимита запросы не меняют пароль и не завершают сессии.

## Подключение к существующему API-клиенту

В `frontend/src/types/api.ts` добавить тип:

```ts
export interface ChangePasswordRequest {
  current_password: string
  new_password: string
}
```

В `frontend/src/api/client.ts` импортировать этот тип и добавить метод в объект `api`.
Он использует существующие `request`, `csrfToken` и `AuthResponse`:

```ts
async changePassword(payload: ChangePasswordRequest): Promise<AuthResponse> {
  const data = await request<AuthResponse>('/auth/change-password', 'POST', payload)
  csrfToken = data.csrf_token
  return data
},
```

Форма содержит текущий пароль, новый пароль и подтверждение нового. Для текущего
пароля использовать `autocomplete="current-password"`, для двух новых полей —
`autocomplete="new-password"`. Пока запрос выполняется, отключить повторную
отправку. На успехе очистить поля, обновить пользователя из ответа и показать:
«Пароль изменён. Остальные сессии завершены». Доступ к форме нужен обеим ролям.
Пароли не сохранять в localStorage/sessionStorage и не писать в логи.

Автоматически повторять запрос после таймаута или сетевой ошибки нельзя: смена
могла сохраниться. Сначала перечитать `/auth/me`; если сессия потеряна, предложить
войти с новым паролем. Если получен 200 от me, обновить CSRF, но не считать это
доказательством успешной смены: me подтверждает только состояние сессии.

Текущий mock-транспорт этого маршрута пока не реализует. Для проверки backend
использовать режим `real`; поддержку mock добавляет владелец frontend.

## Что проверить после подключения

1. Неверный текущий пароль подсвечивает поле, пользователь остаётся в системе.
2. Короткий/слишком длинный новый пароль и несовпадающее подтверждение обрабатывает форма.
3. После успеха текущая страница работает, последующий POST с новым CSRF проходит.
4. Другой браузер с тем же аккаунтом получает 401. Другая учётная запись продолжает работать.
5. Старый пароль не позволяет войти, новый позволяет. То же работает для администратора.
6. 429 показывает ожидание, сетевой сбой не вызывает автоматическую повторную отправку.
