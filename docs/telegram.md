# Telegram: команды и проверки

## Что показывает бот

Бот читает настоящий API под отдельным обычным пользователем. Данные не копируются в локальную базу. Финансовые команды и их кнопки работают только в чате из `CHAT_ID`; `/start`, `/help`, `/id` и `/site` доступны для первоначальной настройки.

| Команда | Результат |
| --- | --- |
| `/payments` | Неоплаченные периоды со сроком сегодня и в следующие шесть дней |
| `/overdue` | Все просроченные неоплаченные периоды, включая историю прекращённых правил |
| `/all` | Все сохранённые периоды: оплаченные и неоплаченные, без ограничения ближайшей неделей |
| `/summary` | Сводка текущего месяца по срокам платежей, отдельно для RUB, USD и EUR |

Списки загружаются с сервера страницами по пять записей. Кнопка карточки содержит UUID — постоянный идентификатор периода. Даже если список изменился после появления кнопки, она открывает тот же период. Карточка перечитывает статус, дату оплаты и состояние регулярного правила из API.

Сводка использует `/payments/summary`, а не сумму видимой страницы. `planned` — весь план месяца, `paid` — оплачено, `unpaid` — не оплачено; `overdue` уже входит в `unpaid`. День и часовой пояс сообщает API. История и просрочка не зависят от часов компьютера, где запущен бот.

Эти команды только читают данные. Оплату отмечают в веб-панели. Автоматические напоминания отправляет единственный процесс `worker` через постоянную очередь: остановка и повторный запуск бота не создают второй планировщик.

## Настройка и обновление

Порядок Docker-запуска приведён в [README](../README.md#telegram-бот-в-docker). Для чтения нужны `API_BASE_URL`, `API_USERNAME`, `API_PASSWORD` и разрешённый `API_ORIGIN`. Используется cookie-сессия обычного пользователя; `API_TOKEN` не нужен. Публичная `/id` работает без API-настроек и помогает заполнить `CHAT_ID`.

После изменения настроек пересоздайте контейнер бота. После изменения Python-файлов или текстов пересоберите его с `--build`. Модули `bot.py`, `api.py`, `features.py`, `formatting.py`, `reminders.py`, `smoke.py` и `texts.json` входят в образ; рабочий `.env` в него не копируется. Переменные окружения процесса имеют приоритет над локальным `.env`.

## Проверка без отправки

`python smoke.py` печатает локальные примеры для трёх валют, длинного названия и HTML-символов. API и Telegram для этого не нужны. `python smoke.py --backend --dry-run --limit 3` читает первые три периода из настроенного API и тоже только печатает текст. `--from-api` — синоним `--backend`, `--kind overdue` выбирает просрочку, `--limit` принимает 1–100.

Отправка возможна только с явным `--send`. Она обходит очередь и не сохраняет подтверждение доставки, поэтому повторная ручная отправка может продублировать сообщение. Для обычной эксплуатации используйте `worker`, не запускайте smoke по расписанию.

Полная проверка команд: `python scripts/check_bot_api.py --timezone Asia/Tokyo`. Она создаёт отдельную PostgreSQL-базу, настоящий API и случайные учётные данные; рабочий `.env` не использует. Telegram заменён локальным адаптером в закрытой Docker-сети. Проверяются страницы, права чата, карточки по UUID, сводка, восстановление сессии и smoke. Временные ресурсы удаляются после проверки. Это проверка интеграции приложения, а не подтверждение доставки через настоящий Telegram.

## Если что-то не работает

- Финансовая команда недоступна: сравните `/id` с `CHAT_ID` и пересоздайте контейнер после изменения настройки.
- API не настроен или вход не удался: проверьте адрес, обычного пользователя, пароль и `API_ORIGIN`. Имя `backend` доступно внутри Docker; с компьютера используйте адрес сайта с `/api/v1`.
- Сервер ограничил попытки входа: дождитесь `Retry-After`; перезапуск бота не снимает лимит.
- Старая карточка больше недоступна: обновите список. Бот не подменяет отсутствующий UUID другой записью.
- Неверная дата или неполная сводка: проверьте общий `APP_TIMEZONE` и состояние worker. При `503 PERIODS_NOT_READY` дождитесь восстановления периодов и повторите запрос.
