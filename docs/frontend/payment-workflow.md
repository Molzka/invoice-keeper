# Ввод платежей, предварительные даты и ссылки на отфильтрованные списки

## Сумма регулярного платежа

Поле принимает целую сумму или дробную часть через запятую либо точку:

| Ввод | Строка в запросе к API |
| --- | --- |
| `45000` | `45000.00` |
| `45000,50` | `45000.50` |
| `45000.50` | `45000.50` |
| `45000,5` | `45000.50` |

Нормализация выполняется перед отправкой формы; ввод во время набора не переписывается. Удаляются пробелы по краям и лишние ведущие нули, дробная часть дополняется до двух знаков. Расчёт не использует `Number` или `parseFloat`, поэтому крупные суммы сохраняют точность. В API передаётся строка.

Разрешены положительные суммы с максимум 12 значащими цифрами целой части и двумя цифрами после разделителя. Ноль, отрицательное значение, экспоненциальная запись, несколько разделителей и лишние дробные знаки дают ошибку поля. Ограничения проверяются до создающего POST; защита от повторной отправки и поведение после неопределённого результата запроса сохранены.

## Три ближайшие даты

В форме регулярного платежа рядом с периодичностью показаны первая дата и два следующих месячных срока. Каждый месяц рассчитывается относительно исходного дня, а в коротком месяце используется его последний день:

- `31.01.2027 → 28.02.2027 → 31.03.2027`;
- `31.01.2028 → 29.02.2028 → 31.03.2028`.

Сокращение февраля не сдвигает следующие месяцы на 28-е или 29-е число. Используются календарные строки `YYYY-MM-DD`, без преобразования через часовой пояс браузера. Некорректная или ещё не заполненная дата не создаёт вымышленных сроков. У верхней границы поддерживаемого диапазона лет форма объясняет, почему доступно меньше трёх дат.

Под датами явно указано: «Это предварительный расчёт. Окончательные сроки рассчитывает сервер». Предпросмотр помогает заполнить форму и не заменяет серверную генерацию периодов.

## Кликабельная сводка

В каждой карточке RUB, USD и EUR доступны четыре ссылки — всего 12 ссылок. Нажатие сохраняет диапазон сроков из ответа сводки, выбирает валюту карточки, сбрасывает страницу на первую и открывает соответствующий список платежей.

| Сумма в карточке | Фильтр списка |
| --- | --- |
| Всего по срокам | Все статусы |
| Оплачено | Оплаченные, включая оплаченные с опозданием |
| Не оплачено | Все неоплаченные, включая просроченные |
| Из них просрочено | Только неоплаченные с `is_overdue=true` |

Сводка остаётся отдельным серверным итогом по трём валютам: её запрос зависит только от диапазона дат. Фильтры валюты и статуса списка не пересчитывают карточки на клиенте. Нулевая сумма также доступна как ссылка и открывает корректный пустой список.

Ссылки имеют понятные доступные имена и клавиатурный фокус. При обычном нажатии фокус переходит к заголовку результатов; ссылку можно скопировать или открыть в новой вкладке. Для reduced motion прокрутка выполняется без плавного движения.

## Фильтры и история в адресе

Параметры находятся внутри hash-маршрута SPA. Например:

```text
#payments?date_from=2026-10-01&date_to=2026-10-31&currency=USD&status=unpaid&limit=6&offset=0
```

Сохраняются применённые границы `date_from`/`date_to`, валюта `currency`, вкладка `status=all|paid|unpaid|overdue`, размер страницы `limit=6|12|24` и её позиция `offset`. В истории выбранного регулярного платежа дополнительно сохраняется `recurring_payment_id`:

```text
#history?status=all&limit=12&offset=0&recurring_payment_id=f0000000-1111-4111-8111-000000000010
```

Обновление страницы и кнопки «Назад»/«Вперёд» восстанавливают список, фильтры, пагинацию и историю выбранного платежа, включая прекращённые платежи. Изменение фильтров или размера страницы возвращает список на первую страницу. Если после изменения данных текущая страница исчезла, адрес корректируется до последней существующей страницы.

Значения из адреса проходят проверку допустимых валют, статусов, календарных дат и параметров пагинации. Неизвестные параметры не передаются в API. Для платежей обязателен ограниченный диапазон сводки, без конца позже текущего месяца; некорректный диапазон заменяется диапазоном по умолчанию. История допускает открытые границы дат.

## Проверки

Ниже сохранены результаты этапа разработки; они не заявляют повторную проверку текущей версии.

- `npm run build`: TypeScript и Vite успешно.
- `npm run lint`: без предупреждений.
- `npm test`: 31 тестовая группа успешно. Покрыты точная нормализация и ограничения сумм, високосные и короткие месяцы, исходный день повторения, границы календаря, сериализация и чтение маршрутов, допустимые и ошибочные фильтры. Сохранены регрессии API-клиента и общей демо-даты; добавлены [регрессии смены пароля](password-change.md).
- Через форму в браузере созданы демо-платежи с вводом `45000`, `45000,50`, `45000.50`; подтверждены значения `45000.00` и `45000.50`. После проверки демо-набор восстановлен обновлением страницы.
- На настольной ширине и 320 px проверены три даты, отсутствие горизонтального переполнения, клавиатурный переход по сводке, фильтры оплаченных с опозданием и просроченных, нулевая сумма, обновление страницы и «Назад»/«Вперёд».
- Проверены сохранение пагинации и истории прекращённого платежа, обе роли, а также крупные суммы в стрессовом демо-наборе.

Проверки интерфейса выполнены с демонстрационным API. Полный backend/Docker и e2e с реальной базой данных в этой задаче не запускались.
