# Календарь оплат и журнал действий

## Календарь

Календарь показывает обязательства по **сроку оплаты**. Обе роли могут выбрать месяц, день, валюту и статус, открыть платёж, отметить оплату, исправить её дату или перейти в историю регулярного платежа. На компьютере используется месячная сетка с понедельника, на телефоне — список по дням. Прекращённые платежи сохраняются в истории.

Месяц, день и фильтры записываются в `#calendar?...`, поэтому ссылка, обновление страницы и переходы назад/вперёд сохраняют выбранный вид. Например, `#calendar?month=2026-10&day=2026-10-24&currency=USD&status=overdue` открывает просроченные долларовые платежи за октябрь.

Календарь получает периоды через `GET /api/v1/payment-occurrences`, а общая панель оплаты использует `GET/PATCH /api/v1/payment-occurrences/{id}`. За месяц загружаются все страницы по 100 записей. При неполной или противоречивой выдаче показывается ошибка с повтором. Валюты не складываются; суммы передаются строками с двумя знаками после точки.

Показаны только уже сформированные сервером периоды. Пустой будущий месяц не означает отсутствие расходов: периоды могут ещё не существовать. Календарь не создаёт прогнозные обязательства.

## Дата и часовой пояс

В настоящем режиме текущий день и ограничения даты оплаты используют поле `timezone` из ответов API `/auth/login` и `/auth/me`. Оно соответствует серверному `APP_TIMEZONE` — имени IANA, например `Europe/Moscow` или `Asia/Tokyo`. Часовой пояс компьютера не меняет календарную дату платежа. Итоговые статусы и опоздание определяет сервер.

При наступлении нового дня в этом поясе календарь перечитывает периоды, чтобы обновить просрочку. Открытая панель оплаты сохраняет введённую, но ещё не отправленную дату: смена дня не должна затирать работу пользователя. Часы проверяются каждые 30 секунд и при возвращении фокуса на страницу.

Для смены `APP_TIMEZONE` следуйте [настройкам приложения](../operations/configuration.md): обновите общий параметр сервисов, пересоздайте их и перезагрузите страницу, чтобы получить новый пояс из API. Сохранённые `due_date` и `paid_on` не переписываются.

Демо использует фиксированную дату **23 октября 2026 года** и пояс `Europe/Moscow` из `src/config/demo.ts`. Эти значения не заменяют настройки настоящего сервера.

## Журнал действий

Раздел «Журнал» доступен администратору. Он показывает автора, время, действие и объект изменения; поддерживает поиск, фильтры, страницы и подробности со значениями до/после. Условия сохраняются в `#activity?...`. «Сбросить» очищает также неприменённые поля и ошибку диапазона.

В режиме `real` события загружаются через `GET /api/v1/audit-events`. Для подключения нужны миграции до `0006`: `0005` добавляет журнал, `0006` — подтверждения оплаты. Порядок обновления описан в [корневом README](../../README.md). Роль `user` получает `403` при прямом запросе журнала. Ошибки API показываются с возможностью повтора; демонстрационные события вместо них не подставляются.

Событие сохраняется в одной транзакции с успешной операцией. Если операция отклонена или данные не изменились, нового события нет. Снимки автора и названия объекта переживают удаление и переименование. Прошлые изменения, выполненные до подключения аудита, задним числом не восстанавливаются.

Журнал отражает создание и прекращение платежей, оплату, отмену и исправление её даты, управление пользователями, смену собственного пароля и изменение подтверждения оплаты. У платёжных событий `entity.id` указывает на регулярное правило: из подробностей можно открыть всю историю периодов. Время задаёт сервер; группировка и фильтры дат используют общий часовой пояс.

Пароли, их хеши, cookie и CSRF в события не включаются. Для подтверждений оплаты сохраняются только факт изменения, тип и период; URL, имя файла и содержимое не записываются. Подробный контракт и устройство транзакций — в [памятке backend](../api/calendar-audit-integration.md).

В режиме `mock` журнал содержит примеры и успешные изменения в текущей вкладке. Эти данные находятся в памяти и сбрасываются при перезагрузке. Смена собственного пароля доступна обычному пользователю; аккаунт администратора защищён в обоих режимах.

## Бюджет и подтверждения оплаты

API бюджета месяца/года и сохранения одного файла или HTTPS-ссылки уже доступны. Их отдельные экраны ещё не реализованы. Прикрепление подтверждения и отметка оплаты — независимые операции. Контракты, ограничения и примеры запросов находятся в [памятке бюджета и чеков](../api/budget-receipts.md).

## Использование и диагностика

- Для просмотра примеров запустите Vite в `mock` или явно соберите Docker с `FRONTEND_API_MODE=mock`. Docker по умолчанию работает с настоящим API.
- Для проверки настоящего сохранения и трёх валют используйте [демонстрационный сценарий](../operations/demo-data.md) на отдельном стенде. Из календаря можно пройти оплату, исправление даты и историю, а затем увидеть события в журнале администратора.
- Если календарь пуст, проверьте месяц, валюту, статус и наличие сформированных периодов. Кнопка «Сегодня» возвращает текущий месяц, а «Обновить календарь» повторяет загрузку.
- Если дата отличается от ожидаемой, проверьте `timezone` в ответе `/auth/me` и `APP_TIMEZONE` сервера, затем перезагрузите страницу. Настройка часов браузера не меняет пояс приложения.
- Если журнал отвечает `404`, проверьте версию API и подключение маршрута; при ошибке таблиц — применение миграций. Пустой журнал после первого обновления допустим: выполните новое изменение и повторите загрузку.

При изменениях проверьте `npm test`, `npm run typecheck`, `npm run lint` и `npm run build`. Существующий `e2e/calendar-audit.spec.ts` проходит календарь и серверный журнал на отдельном стенде. При изменении работы часов дополнительно проверьте смену дня с открытой панелью и несохранённой датой, а также настольную и мобильную раскладки.
