# Проверка по исходному ТЗ — 25 октября 2026

Проверены исходники ревизии `4d5bde9` и исправление выхода между вкладками в рабочем дереве. Источник — предоставленный PDF «Invoice Keeper — напоминания о регулярных платежах», 18 страниц. Проверки выполнялись на свежих Docker-образах с отдельными PostgreSQL, учётными записями и тестовыми данными. Рабочий стенд не использовался для создания, изменения или удаления тестовых платежей.

## Результат

В проверенных сценариях обязательная часть ТЗ выполняется. Найден и исправлен дефект интерфейса после выхода; исправлены две неточности инструкции запуска. Остальных подтверждённых нарушений обязательной части не обнаружено. Это результат перечисленных проверок, а не гарантия отсутствия любых ошибок во всех окружениях.

### Исправления

1. **Выход в соседних вкладках.** API отзывал сессию, но уже открытая соседняя вкладка продолжала показывать закрытый раздел до ручного обновления или следующего запроса. Старый браузерный тест проверял её только после `reload`, поэтому пропускал дефект. Добавлена проверка экрана входа без ручной перезагрузки: до исправления она падала по тайм-ауту. Теперь после успешного logout вкладки одного origin получают сигнал через `BroadcastChannel` и перезагружают приложение. Это отменяет старые запросы, удаляет данные и формы из памяти страницы и проверяет сессию сервером. Сигнал не содержит секретов; режим mock остаётся независимым по вкладкам.
2. **Миграции в frontend README.** Устаревшее указание `0006` заменено на `alembic upgrade head`; текущий head — `0008`, включая MFA и заявки.
3. **Полнота запуска.** В корневом README явно указано, что worker обязателен для следующих месячных периодов, а не только для Telegram. Запуск одной веб-панели не включает фоновые задачи.

Локальная ошибка поиска `altcha` и `qrcode` оказалась состоянием зависимостей: системный Node `24.13.0` не удовлетворял закреплённому `24.22.x`. Установка через Node `24.22.1` и npm `11.6.2` восстановила зависимости без изменения lockfile и без ослабления проверок.

### Условия и границы

- «Напомнить сразу» реализовано как немедленная готовность задания после commit. Фактическая отправка — ближайший цикл worker; по умолчанию пауза 30 секунд плюс обработка. Для приёмки следует показывать это поведение, не обещая синхронную отправку внутри POST.
- `unknown` после неопределённого сетевого результата требует проверки оператором. Автоматического повтора нет, поскольку Telegram мог принять первое сообщение. Это защищает от дублей, но не гарантирует доставку при любом сбое внешнего сервиса.
- История и сводка зависят от работающего worker при переходе к новым периодам. При неполной истории сводка возвращает `503 PERIODS_NOT_READY`, а не ложные нули.
- Живое получение сообщения в Telegram не проверялось: вместо внешней отправки использовались локальный HTTP-приёмник и синтетические Update. Для завершения живой приёмки нужны выделенный тестовый чат/бот и явное разрешение отправить туда тестовые сообщения. Наличие настроек в рабочем `.env` не подтверждает доставку в чат.
- Прогон выполнен в Chromium. Работа Safari/Firefox и нагрузка большого числа пользователей отдельно не проверялись.
- Исправление собрано и проверено на изолированном стенде. Рабочие контейнеры `invoice-keeper-*` не обновлены до новых исходников в рамках этой проверки.
