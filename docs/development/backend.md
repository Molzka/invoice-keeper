# Разработка backend

## Локальный запуск backend

Для разработки backend необходимы Python 3.12+, менеджер зависимостей [uv](https://docs.astral.sh/uv/) и PostgreSQL. Локально используем PostgreSQL 18 в Docker.

Перейдите в каталог backend:

```powershell
cd backend
```

Установите зависимости из зафиксированного `uv.lock`:

```powershell
uv sync --locked
```

Создайте локальный файл окружения, если его ещё нет (PowerShell):

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

Файл `backend/.env` содержит локальные настройки и секреты и не должен попадать в Git. В `DATABASE_URL` укажите фактические имя пользователя, пароль, порт и базу из корневого `.env` для Compose. Шаблон использует `127.0.0.1:5432`, пользователя и базу `invoice_keeper`; `replace_me` нужно заменить. Специальные символы пароля в URL должны быть percent-encoded. Корневой `.env` настраивает Docker, а `backend/.env` — Python-приложение.

PostgreSQL запускается из корня проекта после настройки корневого `.env`:

```powershell
docker compose up -d --wait postgres
```

Если раньше была создана отдельная база `invoice-keeper-db-dev` на порту `55432`, её можно продолжать использовать: запустите `docker start invoice-keeper-db-dev` и оставьте соответствующий URL в `backend/.env`. Не создавайте новую базу вместо существующей без переноса нужных данных. Команды `uv` ниже выполняются из каталога `backend`.

В `backend/.env` задайте `ADMIN_USERNAME` и свой `ADMIN_PASSWORD` длиной 8–128 символов. Пароль со специальными символами можно заключить в одинарные кавычки. Затем примените миграции и создайте первого администратора:

```powershell
uv run --locked alembic upgrade head
uv run --locked python -m app.cli create-admin
```

Команда читает настройки из `backend/.env` и не спрашивает пароль в терминале. Если логин или пароль не заполнены, она завершится с понятной ошибкой. Переменные окружения процесса имеют приоритет над `.env`; это позволяет передавать настройки при автоматическом запуске. Пароль не выводится в журнал, в PostgreSQL сохраняется его Argon2-хеш.

Повторный вызов с занятым логином завершится ошибкой и сохранит существующий аккаунт и пароль. Изменение `ADMIN_PASSWORD` в `.env` само по себе не меняет пароль уже созданного администратора. Для существующей базы повторно создавать его не нужно; после успешного создания `ADMIN_PASSWORD` можно удалить из `.env`. Сервер API не создаёт и не меняет администратора при каждом старте.

Ручной вариант тоже доступен: `uv run --locked python -m app.cli create-admin --username admin`. В этом режиме пароль и подтверждение запрашиваются без отображения ввода, значения `ADMIN_USERNAME` / `ADMIN_PASSWORD` не используются. Миграция `0002` переводит роль `member` в `user`, сохраняя пользователей, хеши паролей, сессии и ранее введённые имена.

Запустите сервер:

```powershell
uv run --locked uvicorn app.main:app --reload --no-proxy-headers
```

После запуска доступны:

- Swagger UI: http://127.0.0.1:8000/api/v1/docs
- OpenAPI JSON: http://127.0.0.1:8000/api/v1/openapi.json
- Проверка работы API: http://127.0.0.1:8000/api/v1/health
- Проверка подключения к БД: http://127.0.0.1:8000/api/v1/ready

Остановить сервер можно сочетанием `Ctrl+C`.

Для локального запуска через uv используем `--no-proxy-headers`, чтобы IP-лимит входа не зависел от присланного клиентом `X-Forwarded-For`. В Docker запросы идут через [настроенный Nginx](../operations/deployment.md#backend-в-docker). Запуск готового обработчика напоминаний описан в [разделе доставки](../operations/reminder-integration.md#доставка-напоминаний-интеграция-с-платежами).

### Экспорт OpenAPI для передачи решения

Файл [backend/openapi.json](../../backend/openapi.json) хранится вместе с кодом и дополняет работающий Swagger. После изменения маршрутов или схем обновите его из корня проекта:

```sh
cd backend
uv run --locked python scripts/export_openapi.py
uv run --locked python scripts/export_openapi.py --check
```

Первая команда сохраняет актуальную спецификацию; `--check` проверяет совпадение файла с текущими схемами, не перезаписывая его. Экспорт не требует запущенной БД, не применяет миграции и не отправляет сообщения. Команды выполняются в `backend`; затем вернитесь в корень через `cd ..` для команд Docker Compose.
