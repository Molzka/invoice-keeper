# Доступ сотрудников и подтверждение входа

## Как сотрудник получает доступ

На странице входа нажмите «Запросить доступ», укажите желаемый логин, пароль с повтором и имя или короткое сообщение администратору. Пройдите проверку защиты от спама и отправьте заявку. Это ещё не аккаунт: платежи и другие данные до одобрения недоступны.

Администратор рассматривает заявки в разделе пользователей. Одобрение создаёт обычного пользователя с выбранными учётными данными; отклонение не создаёт аккаунт. Пароль сразу хешируется и никогда не показывается администратору. После решения его хеш удаляется из заявки. В журнале остаётся решение и имя администратора, без паролей и сообщения сотрудника.

Для одного логина может быть только одна ожидающая заявка. Публичный ответ одинаков для новой заявки, уже ожидающей заявки и существующего аккаунта: посторонний не получает список занятых логинов. После одобрения войдите обычным способом. Если ожидание затянулось, обратитесь к администратору компании; уведомление о решении на неизвестный Telegram-аккаунт не отправляется.

Сервис остаётся внутренним. Администратор проверяет, что заявитель — сотрудник; CAPTCHA сама по себе этого не доказывает. Прямое создание пользователя администратором также сохранено. Учётная запись администратора создаётся из настроек сервера и защищена от изменения через панель, включая самостоятельное подключение MFA.

## Когда нужен второй код

Без MFA достаточно логина и пароля. Подключение дополнительной защиты добровольное: предложение можно пропустить и позже вернуться в «Безопасность». Права и функции от выбора не меняются.

После подключения MFA при каждом новом входе требуется второй код. Успешная проверка пароля сама по себе ещё не открывает сайт. Можно выбрать любой заранее подключённый способ:

| Способ | Откуда берётся код |
| --- | --- |
| Приложение-аутентификатор | Приложение на телефоне, обычно новый код каждые 30 секунд |
| Telegram | Личное сообщение нашего бота после запроса на странице входа |
| Резервный код | Сохранённый при подключении набор; каждый код используется один раз |

Номер Telegram и `@username` вручную вводить не нужно. При первом подключении сайт выдаёт одноразовую ссылку. Откройте её, запустите бота и вернитесь в тот же браузер. Проверьте показанный аккаунт и введите присланный ботом код. Только после этого привязка начинает работать. Если открыть ссылку с другого Telegram-аккаунта, сайт покажет именно его: не подтверждайте ошибочную привязку, начните настройку заново.

Ссылка действует десять минут, присланный код и запрос входа — пять минут. Повторная отправка доступна не раньше чем через минуту. Пять неверных кодов исчерпывают запрос подтверждения. Приложение-аутентификатор использует время телефона: включите автоматическую синхронизацию часов. Уже использованный TOTP-код повторно не принимается, дождитесь следующего.

## Резервные коды и изменение защиты

При первом подключении показываются десять резервных кодов. Сохраните их в менеджере паролей либо другом защищённом месте отдельно от телефона. Они показаны только один раз. Повторная генерация выдаёт новый набор и сразу отзывает прежний.

Чтобы добавить, заменить или удалить способ, сначала подтвердите пароль. Если MFA уже включена, нужен также текущий второй фактор или резервный код. Одного пароля недостаточно. Такое подтверждение разрешает одно изменение в течение пяти минут; сама настройка нового способа остаётся привязана к исходному браузеру и текущей версии защиты.

Изменение способов отозывает другие открытые сессии и незавершённые запросы входа. При удалении последнего способа MFA выключается, резервные коды отзываются, следующий вход снова требует только пароль. Смена пароля администратором не снимает уже подключённую MFA. При потере всех факторов и резервных кодов автоматического обхода защиты нет.

## Telegram: два независимых назначения

`CHAT_ID` задаёт общий чат финансовых напоминаний. Он не используется для личных кодов. Код первой привязки идёт в личный чат с положительным числовым Telegram ID, который бот получил из Telegram Update. Коды входа отправляются только после подтверждения этого аккаунта на сайте. Смена `@username` не разрывает привязку; один Telegram-аккаунт нельзя одновременно подключить к двум пользователям сайта.

Служебный пользователь `API_USERNAME`/`API_PASSWORD` нужен боту только для чтения платежей. Его нельзя выдавать сотрудникам как личный аккаунт. Если включить для него MFA, автоматический вход финансового клиента потребует второй фактор и перестанет работать: специального обхода нет. Личная привязка использует отдельный внутренний маршрут и секрет, а не эту учётную запись.

## Подготовка сервера

Перед обновлением сохраните резервную копию базы, затем примените миграции до `0008` по [инструкции обновления](deployment.md). Миграции добавляют таблицы и поля; существующие пользователи получают выключенную MFA, их доступ не меняется.

Дополнительные настройки корневого `.env`:

| Переменная | Назначение и доступ |
| --- | --- |
| `MFA_ENCRYPTION_KEY` | Постоянный Fernet-ключ для секретов MFA; только backend |
| `BOT_INTERNAL_TOKEN` | Отдельный случайный секрет связи bot → backend; оба контейнера |
| `BOT_USERNAME` | Настоящее имя бота из BotFather, без `@`; backend строит ссылку |
| `BOT_TOKEN` | Существующий токен бота; backend отправляет личные коды, worker — напоминания |
| `BOT_INTERNAL_BASE_URL` | Внутренний адрес backend для бота; в Compose `http://backend:8000` |

Создайте ключи один раз на своём компьютере. Из каталога `backend` после установки зависимостей:

```sh
uv run --locked python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
uv run --locked python -c "import secrets; print(secrets.token_urlsafe(32))"
```

Первый результат сохраните в `MFA_ENCRYPTION_KEY`, второй — в `BOT_INTERNAL_TOKEN`. Не вставляйте их в переписку, коммиты или общие логи. Fernet-ключ сохраните отдельно от дампа БД: без него нельзя расшифровать TOTP-секреты после восстановления. Не генерируйте новый ключ при каждом запуске. После изменения настроек пересоздайте backend и bot; после изменения кода пересоберите их. Worker продолжает свой прежний сценарий доставки напоминаний.

Без ключа шифрования подключение MFA недоступно. Уже подключённый фактор при пропавшем или неправильном ключе не превращается во вход по паролю. Для восстановления сначала верните правильную конфигурацию. В production обязательны HTTPS и защищённые cookies, как и для обычной авторизации.

CAPTCHA ALTCHA работает локально: браузер решает ограниченную вычислительную задачу, сервер проверяет подписанный ответ и удаляет одноразовую запись. Внешний аккаунт, sitekey и отправка пользовательских данных провайдеру не нужны. Это повышает стоимость автоматической отправки; дополнительно действуют ограничения запросов и ручная модерация. Очистка `python -m app.cli cleanup-auth` удаляет истёкшие запросы подтверждения и CAPTCHA вместе с прежними временными данными авторизации.

## Если что-то не работает

- **Заявка не даёт войти:** проверьте её статус у администратора. До одобрения пароль не создаёт сессию.
- **Проверка от спама истекла:** повторите её. Использованный ответ не подходит для другой заявки.
- **CAPTCHA не запускается по HTTP-адресу в локальной сети:** браузер требует безопасный контекст для криптографических вычислений. Используйте HTTPS; для разработки допустим `http://localhost` или `http://127.0.0.1`. Не отключайте проверку на сервере.
- **Telegram не появился среди способов входа:** сначала подключите его в «Безопасности» и подтвердите кодом на сайте.
- **Не приходит личный код:** проверьте, что бот не заблокирован, открыта личная переписка и сервер имеет доступ к Telegram. Общий `CHAT_ID` здесь не поможет; используйте аутентификатор или резервный код.
- **Ссылка использована либо истекла:** начните привязку заново. Повторное нажатие старой ссылки не заменяет привязанный аккаунт.
- **Код уже принят:** используйте следующий код приложения или другой резервный код. Повтор защищён от параллельного использования.
- **MFA недоступна после обновления:** проверьте наличие прежнего ключа шифрования и миграции. Не отключайте проверку фактора ради восстановления входа.
- **Слишком много попыток:** дождитесь указанного `Retry-After`. Перезапуск контейнера лимит не сбрасывает.

Технические маршруты и ограничения описаны в [контракте доработки](../development/access-security-plan.md) и [OpenAPI](../../backend/openapi.json). MFA — многофакторная аутентификация; TOTP — код, вычисляемый по секрету и времени; recovery code — одноразовый резервный код; deep link — ссылка, передающая боту случайный параметр запуска.
